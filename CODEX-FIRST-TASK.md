# First Codex task — Build the Tetsao Party visual prototype

You are working inside the `party` project root. Read and obey `AGENTS.md` first. Inspect all four images in `design-reference/` before making design decisions. If any image cannot be read, report the limitation and use the other images and the theme descriptions in `AGENTS.md`.

Build a fully functional **local visual prototype** of `tetsao.party`, with a shared responsive HTML structure and four distinctive themes inspired by the references: Magic, Utah Game Day, Retro Arcade, and RC Trail. The user values fidelity to the visual references over generic UI. Each theme should have genuinely distinct design details, typography, background treatments, entry-card appearance, and service tiles, not just a color swap. Prefer lightweight vanilla HTML/CSS/JS. Use accessible and responsive design, including mobile layout, keyboard navigation, and reduced-motion support. Keep assets and fonts licensed or original. Do not ship the design-reference mockup images as the website itself.

Implement a theme selector with Random as the default. Random chooses one of four themes per fresh page load; manually selected themes persist in localStorage and take effect immediately. Provide a `Prove You Know Tom` question card as a **visual demo only** in this first phase—do not pretend it is real authentication or put real answers in the browser. Implement the six service tiles for Zima Admin, Zima VM, Jellyseerr, Jellyfin, Audiobookshelf, and Immich; use clearly labeled unconfigured destinations instead of guessing hostnames, and do not create links pointing to live private systems yet.

Prepare for deployment via Cloudflare Workers Static Assets with a minimal `package.json` and `wrangler.jsonc`, following the current Cloudflare-supported configuration. Separate static assets into `public/`; do not expose security secrets or `design-reference/`. Include a `README.md` with local preview instructions, theme behavior, file layout, and a checklist for later Cloudflare setup and hardening. If there is no existing repository, initialize Git locally and add a `.gitignore`. You may create, edit, install local project dependencies if needed, and run tests; do not deploy, authenticate to a Cloudflare account, change DNS/Tunnel/Access, or change anything on ZimaOS.

At completion, run the available local checks and summarize: implemented features, local preview command/URL, files changed, checks performed, and known visual gaps relative to the four reference images. Proceed autonomously with reasonable design decisions rather than asking minor clarification questions.
